# Quantum Shield Roadmap

Version 1.0 | 4 October 2026 | Delivery gates, not guaranteed dates

## Live: public evidence beta

- Free Wallet Scanner, Token Check, and Wallet Compare on Ethereum and Base.
- Website source review with bounded collection, rule evidence, and AI-selected excerpts.
- Domain reputation and URL-pattern checks with explicit uncertainty.
- Recent Ethereum and Base activity combined into a timestamped timeline.
- Local image header/filename comparison, explicitly not antivirus.
- Owner-only workspace for saved evidence and manual watch checks.
- Public documentation and white paper; no payments, token deployment, or open company onboarding.

The animated network map and example scores remain demonstrations. Quantum Vault, automatic asset protection, and comprehensive quantum-risk measurement are not live products.

## Next: validate detection and improve coverage

Build and maintain a labeled corpus of legitimate pages, approval flows, deceptive sites, code obfuscation, redirects, and prompt-injection cases. Measure false positives, false negatives, scan failures, and coverage instead of inventing a universal safety percentage. Establish a correction workflow and independent review.

Improve source collection with controlled isolation, broader script coverage, timeout budgets, provenance, and content-change detection. An isolated browser must have no customer wallet secrets or funds and no access to internal services. A scan blocked by a website must remain visibly incomplete.

## Wallet-action analysis

Capture wallet-method requests in a controlled environment. Interpret signatures and approvals, inspect recipients and spenders, and simulate transaction effects where the network and provider support them. Include Permit/Permit2 authorization scope and replay risks in the review. Release only after benign and hostile fixtures demonstrate the supported behavior and failure boundaries.

Simulation must state the chain, state/block, request, and limitations. A simulated request must never be described as a guarantee about every future action on a domain.

## Broader wallet intelligence

Add full pagination, internal transfer coverage, network-specific adapters, bridge evidence, and verified address labels. Validate Ethereum/Base depth first, then expand by documented provider coverage. Bitcoin and Solana require different account and data models; a logo or RPC URL is not evidence of support.

Exchange destinations require attributed evidence and freshness. Unknown destinations remain unknown. The product will help assemble onchain reports but will not promise an exchange listing or infer private exchange-internal movements.

## Company services and reliability

Add customer identity, independently tested tenant isolation, supported public API keys, pagination, exports, retention/deletion workflows, verified backups, and incident ownership. Enable unattended monitoring and email only after observing reliable delivery, recovery, and deduplication. Obtain rights and quotas for commercial data use before promising availability.

Validate repeat use with company design partners. Price recurring workflows, data depth, and support against actual operating costs. Basic individual tools remain a free entry point; paid features require clear scopes and published terms.

## QUS service payments

QUS is the planned service-payment token with a planned total supply of 1,000,000,000 QUS. Select the network and contract design, verify supply behavior, obtain security review, publish official deployment details, and test supported service payments before launch. No tokenomics, allocations, vesting schedule, or token sale is specified here.

Payment must be an explicit user action with a service description, exact amount, asset, recipient, network, and expiry. Holding a token does not currently unlock a feature.

## x402 agent micropayments

Implement a versioned agent API and x402 payment requirements, verification, settlement, receipts, duplicate-charge protection, and result recovery. Confirm accepted assets and facilitator support rather than assuming every ERC-20 token works with every provider. Evaluate XPay as a candidate integration.

Test a small-price model, including an illustrative US$0.01-equivalent target for selected lightweight lookups. Publish the actual service price and total charges before accepting payment. More expensive AI, licensed data, or simulation can require different pricing. Enforce agent spending ceilings and validate the recipient, network, asset, and quote expiry.

## Post-quantum readiness research

Develop cryptographic inventory and migration-readiness workflows with qualified reviewers. Evaluate candidate account policies in test environments. A future Quantum Vault requires a reviewed threat model, implementation, recovery design, independent assessment, and controlled deployment before any protection claim.

The existing beta and planned QUS token are not described as quantum-resistant. No new blockchain launch or quantum-threat deadline is promised.

## Commercial release gate

Paid launch requires useful validated reports, reproducible evidence, adequate provider coverage, tested access controls, defined operations and support ownership, payment/recovery tests, published privacy and service terms, and appropriate review for the operating entity and jurisdictions. Calendar dates will be added only when dependencies and capacity are confirmed.
